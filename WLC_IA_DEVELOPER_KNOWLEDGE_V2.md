# WLC.IA — Developer Knowledge Pack v2.0

This knowledge pack is curated engineering guidance used by retrieval; it is **not model-weight training** and does not replace the active provider's capabilities, current documentation, execution tools, or verification.

## Domains
- Semantic HTML, accessibility, SEO foundations
- Responsive CSS, layout systems, design tokens, motion preferences
- Modern JavaScript, asynchronous execution, DOM safety, scripting
- TypeScript strictness, type modeling, runtime schemas
- React component design, hooks, state, UI architecture
- Modular architecture, SOLID, pragmatic patterns and incremental refactoring
- Backend services, REST contracts, HTTP semantics, errors, reliability
- PostgreSQL/SQL, schema design, migrations, constraints, indexes, transactions
- Authentication, authorization, OWASP threats, secret management
- Unit/integration/E2E testing, lint, typecheck, build, regression tests
- Debugging, root-cause analysis, observability
- Git, branches, CI/CD, releases and rollback planning
- Performance profiling, caching and scalability
- Product requirements, UX, dashboard/SaaS patterns and acceptance criteria
- Scripts, CLI, automation, workers, idempotency and dry-run safety
- LLM systems, retrieval, tool schemas, prompt injection defenses and evaluations
- Code review and professional delivery evidence

## Professional development workflow
1. Clarify goal, constraints, user flows, existing behavior and acceptance criteria.
2. Inspect repository, stack, package scripts, conventions, architecture and current changes.
3. Design a proportional solution with module boundaries, data contracts, security and failure states.
4. Implement end-to-end, incrementally; avoid mock-only or placeholder completion.
5. Review types, inputs, permissions, accessibility, responsive behavior, loading/empty/error states and secrets.
6. Run available tests, lint, typecheck, build and targeted checks; report only commands actually run.
7. Inspect diff and summarize delivered changes, verification, limitations, risks and next steps.

## Honest capability boundary
Knowledge retrieval improves the agent's instructions and domain guidance. It does not independently grant code execution, browser access, repository permissions, new tools, model weights, or guaranteed correctness. The agent must use available tools, inspect their results, and clearly report what could not be executed or verified.
